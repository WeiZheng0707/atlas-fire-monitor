# Atlas 200I DK A2 部署指南

> 本文档按《Atlas 200I DK A2 开发者套件 快速开始》（23.0.RC3）的登录/网络信息编写。
> 目标：PC 训练 → 导出 ONNX → 板端转 OM → 复制运行包 → 启动网页火情监测。
> **数据集只留在 PC，不进板端。**

---

## 1. 交付边界

| 内容 | PC 训练端 | Atlas 板端 |
|---|---|---|
| 数据集 `dataset/` | 需要 | **不需要，不复制** |
| 训练代码 `training/` | 需要 | 不需要 |
| 训练产物 `runs/` | 需要 | 不需要 |
| 模型 `.onnx` | 需要 | 可选（CPU 兜底） |
| 模型 `.om` | 可选（PC 有 CANN） | **推荐** |
| Web/推理代码 `app/` | 可调试 | 需要 |
| 运行依赖 `requirements/board.txt` | 不需要 | 需要 |

打包脚本会显式排除 `dataset/`、`runs/`、`training/`、`tests/`、`tools/`、
`.venv/`、`data/`，并在 `manifest.json` 中写明 `dataset_included: false`。

---

## 2. 板端准备

### 2.1 硬件与系统

- Atlas 200I DK A2 开发者套件（Ascend 310B4）
- 4GB 内存（系统可见约 3.4GB；图形桌面约再占 400MB）
- Micro SD 卡（建议 ≥ 64GB）
- USB 摄像头（接到板端 USB 口，通常为 `/dev/video0`）
- PC 与板端通过 Type-C 或 RJ45 连接

### 2.2 登录信息

| 连接方式 | 板端默认 IP | PC 建议 IP | 登录 |
|---|---|---|---|
| Type-C | `192.168.0.2` | `192.168.0.101` | `ssh root@192.168.0.2` |
| 以太网 eth1 | `192.168.137.100` | `192.168.137.101` | `ssh root@192.168.137.100` |

- 默认用户：`root`，默认密码：`Mind@123`（首次登录后请修改）
- 图形桌面仅 HDMI0 可用；远程 SSH 不需要接显示器
- 首次上电会检查/升级固件，约 1 分钟，期间不要断电

### 2.3 检查 CANN / NPU

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
npu-smi info
python3 -V
```

正常应看到 `Ascend310B4`、Health `OK`。如果 `npu-smi` 不存在，先确认镜像为
Atlas 200I DK A2 的 CANN 镜像，而不是普通 Ubuntu。

> 图形桌面占内存，若只跑服务可关闭（可随时恢复）：
> ```bash
> sudo systemctl disable toggle_graphical_desktop
> sudo reboot
> # 恢复：sudo systemctl enable toggle_graphical_desktop && sudo reboot
> ```

## 3. 从 PC 拷贝运行包

在 PC 的训练工程根目录：

```bash
# 1) 训练并导出（见 training/README.md）
python training/export_onnx.py \
  --weights runs/fire/yolov8n_fire/weights/best.pt \
  --imgsz 640 --opset 12

# 2) 生成板端包（不含数据集）
python deployment/package_for_board.py \
  --model models/fire_yolov8n.onnx
```

输出：

```text
dist/atlas_fire_board_YYYYmmdd_HHMMSS.tar.gz
```

上传并解压（把 IP 换成实际地址）：

```bash
scp dist/atlas_fire_board_*.tar.gz root@192.168.137.100:/home/root/
ssh root@192.168.137.100
cd /home/root
tar -xzf atlas_fire_board_*.tar.gz
cd atlas_fire
```

> 没有 OM 也可以先带 ONNX 上板，用 ONNX Runtime CPU 启动；确认网页与摄像头
> 正常后，再在板端转 OM 切换 NPU。

## 4. 板端安装运行依赖

```bash
cd /home/root/atlas_fire
chmod +x deployment/*.sh
bash deployment/install_board.sh
```

脚本只安装 `requirements/board.txt`：Flask、numpy、opencv-python-headless、
Pillow、onnxruntime，**不会安装 torch/ultralytics**。

如果板端无外网，可在 PC 下载 aarch64 wheel 后拷入，或直接使用镜像中已有的
Python 包；至少需要 Flask、OpenCV、numpy、Pillow。

## 5. 转 OM（推荐，使用 Ascend 310B4）

### 5.1 在板端转换（需要 CANN 的 ATC）

```bash
cd /home/root/atlas_fire
bash deployment/convert_om.sh
```

脚本等价于：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
atc --framework=5 \
  --model=models/fire_yolov8n.onnx \
  --output=models/fire_yolov8n \
  --input_shape="images:1,3,640,640" \
  --input_format=NCHW \
  --soc_version=Ascend310B4 \
  --output_type=FP32 \
  --precision_mode=allow_fp32_to_fp16 \
  --log=error
```

成功生成 `models/fire_yolov8n.om`。

### 5.2 在 PC 上转换（PC 也装了同版本 CANN 时）

在 PC 工程根目录执行同样的 `atc` 命令，把生成的 `.om` 拷到板端：

```bash
scp models/fire_yolov8n.om root@192.168.137.100:/home/root/atlas_fire/models/
```

> `--soc_version` 必须与板端一致；Atlas 200I DK A2 使用 `Ascend310B4`。
> 如果输入名不是 `images`，用 `python3 -c "import onnx;..."` 或 Netron 查看
> ONNX 输入名，并设置 `INPUT_NAME=...` 后运行脚本。

### 5.3 为什么 PC 能转 OM、板端不用再转？

`.om` 不是“模板文件”，而是 ATC **离线编译**后的昇腾模型：

```text
ONNX 计算图 + 权重
      │ ATC（host 端编译器）
      ▼
算子映射/融合 → FP16 精度处理 → 切分/tiling → 内存规划 → 指令/常量序列化
      ▼
.om（绑定目标芯片、CANN 版本、输入 shape 的离线模型）
```

- ATC 是**主机端离线编译工具**，编译时不需要本机插着 NPU；
- `--soc_version=Ascend310B4` 指定“给 310B4 生成”，所以 PC 上生成的是板端
  可执行的 OM，不是 PC 本地推理用的模型；
- 只要 **PC 的 CANN 版本与板端匹配**、ONNX 输入 shape/opset/精度设置一致，
  把 OM 拷到板端即可直接加载，不需要在板端重复编译；
- 反过来，OM **不跨芯片/跨大版本 CANN 通用**。PC 的 CANN 与板端不一致时，
  最稳妥的做法仍是在板端转，或把 PC CANN 换成与板端一致的版本。

> 注意：ATC 需要 Linux 环境（Ubuntu x86_64 / aarch64，具体以所用 CANN 版本
> 支持列表为准）。Windows 原生不能直接执行 `atc`；可在 Ubuntu PC、官方支持的
> Docker 或板端执行。WSL 是否能跑取决于 CANN 版本，课程环境建议直接用 Ubuntu。

### 5.4 为什么转换感觉非常久？

ATC 不是“改个后缀”，而是在做真正的离线编译，耗时主要来自：

1. **图优化**：常量折叠、算子融合、删除冗余节点；
2. **算子适配**：把 ONNX 算子映射到昇腾算子库；YOLOv8 的
   `Split/Concat/Resize/Transpose` 等节点较多，逐个匹配和布局转换；
3. **tiling/内存规划**：为 310B4 的片上内存切分输入、特征图和中间结果；
4. **精度处理**：`allow_fp32_to_fp16` 会评估哪些算子可转 FP16；
5. **代码/权重量化与序列化**：生成指令、常量、模型头，写 OM 文件；
6. **板端资源限制**：Atlas 4GB 内存 + SD 卡，CPU 编译和 swap 都会显著变慢；
   同一模型在 PC（尤其多核 CPU/更大内存）上通常会快很多。

YOLOv8n 在 640×640 下，板端几十分钟、PC 几分钟到十几分钟都属常见范围，
取决于 CANN 版本、CPU、内存和算子支持情况。转换一次后 OM 可反复使用，
推理时不再承担编译开销。

**必须重新转 OM 的情况**：换模型/换输入尺寸/换 batch/改动态 shape/换 SoC/
CANN 大版本变化/AIPP 或精度模式变化。只改告警阈值、类别显示文字、网页样式，
不需要重转。

## 6. 启动

```bash
cd /home/root/atlas_fire
bash deployment/start.sh
```

终端会打印：

```text
平台      : Atlas 200I DK A2（aarch64）
NPU       : 可用
模型      : ascend-om / fire_yolov8n.om
摄像头    : USB 摄像头 /dev/video0
访问地址  : http://192.168.137.100:8000/
```

浏览器打开：

```text
http://<板端IP>:8000/
```

### 6.1 指定摄像头/端口

```bash
bash deployment/start.sh --camera 0 --port 8000
# 没有摄像头时可用图片目录做 UI 联调（不会带入数据集）
bash deployment/start.sh --camera dir:samples
```

### 6.2 开机自启（可选）

```bash
sudo cp deployment/atlas-fire.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now atlas-fire
sudo systemctl status atlas-fire
```

服务文件默认工作目录为 `/home/root/atlas_fire`，如路径不同请修改。

| 检查 | 命令/页面 | 预期 |
|---|---|---|
| NPU 可见 | `npu-smi info` | 310B4 / Health OK |

## 8. 常见问题

| 现象 | 处理 |
|---|---|
| `npu-smi: command not found` | 镜像不对或 CANN 未安装；确认是 Atlas 200I DK A2 官方镜像 |
| `atc: command not found` | 未 source `set_env.sh`，或 CANN Toolkit 未装 |
| `ATC` 报 soc_version 错 | 改为 `Ascend310B4`，用 `npu-smi info` 确认芯片 |
| OM 加载失败 | 检查 OM 是否由同一 CANN/芯片转换；看 `/api/health` 的 model.error |
| `ais_bench` import 失败 | 确认 CANN 路径；或先用 ONNX Runtime CPU 兜底 |
| 摄像头黑屏 | `ls /dev/video*`；换 USB 口；确认用户有 video 权限 |
| 页面模型未就绪 | `models/` 中没有 `.om/.onnx`，或路径与 `configs/app.json` 不一致 |
| 板端内存不足 | 关图形桌面；用 yolov8n/640；不要同时跑 Jupyter/训练 |
| 上传图片 500 | 模型未就绪或图片格式不支持；看服务端日志与页面提示 |
| 时间不对 | 板端无 RTC 时手动校时：`date -s "2026-10-20 21:00:00"` |

## 9. 关键路径

```text
/home/root/atlas_fire/
├─ app/                       # Web + 推理
├─ configs/app.json           # 板端配置
├─ models/fire_yolov8n.om     # NPU 模型
├─ models/fire_yolov8n.onnx   # CPU 兜底
├─ models/labels.txt          # 类别
├─ data/events/               # 告警证据（运行时生成）
└─ deployment/                # 转换/启动/安装脚本
```

数据集、训练代码、`runs/` 不在板端；这是刻意设计，减少 4GB 设备的存储和
内存压力，也避免数据泄露。
