## 1. 环境准备

### 1.1 直接用现成的（本机已就绪）

```bash
# Windows CMD
.venv-train\Scripts\activate

# Git Bash / Linux
source .venv-train/bin/activate

python -c "import torch, ultralytics; print(torch.__version__, torch.cuda.is_available())"
# 预期：2.8.0+cu128 True
```

**不要用 `.venv`**。那个目录是从另一台电脑拷过来的，`Scripts/python.exe` 里写死了
`C:\Users\33420\AppData\Local\Programs\Python\Python311\python.exe`，一执行就报
`No Python at '...'`。启动脚本已经做了探测逻辑会跳过它，但你手动敲命令时别去碰。

### 1.2 从零重建

```bash
python -m venv --system-site-packages .venv-train
.venv-train/Scripts/pip install -r requirements/train.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

`--system-site-packages` 是为了复用系统里已有的 torch/torchvision，省下 2GB 下载。
如果机器是干净的，去掉这个参数、改成完整安装即可。

### 1.3 确认依赖齐全

```bash
python -c "
import torch, ultralytics, onnx, onnxruntime, cv2, flask
print('torch', torch.__version__)
print('ultralytics', ultralytics.__version__)
print('onnx', onnx.__version__)
print('onnxruntime', onnxruntime.__version__)
print('cv2', cv2.__version__)
"
```

五个都能打印出版本号才继续。缺哪个补哪个（`ultralytics` 8.4 之后保存模型需要
`polars`，缺了会报 `No module named 'polars'`，直接 `pip install polars`）。

## 2. 三分钟把界面跑起来

### 2.1 插了 USB 摄像头

Windows 直接双击 `run_pc_preview.bat`，等价于：

```bash
python app/main.py --camera 0 --port 8000
```

浏览器打开 <http://127.0.0.1:8000>。

### 2.2 没摄像头（用图片当视频源）

```bash
# 循环播 samples 里的 4 张样例图（火焰 / 合成火焰 / 正常房间 / 暖光台灯）
python app/main.py --camera "dir:samples" --port 8000

# 只播一张
python app/main.py --camera "file:samples/fire_phone.jpg" --port 8000
```

`dir:` 和 `file:` 走的是**与摄像头完全相同**的推理/告警/存证链路，区别只是画面不动。
这是答辩现场最稳的演示方式：不依赖光线、不依赖摄像头被占用。

> `dir:` 会把目录里的图片**一次性读进内存**（最多 200 张，超出自动截断）。所以演示
> 用的目录放十几张就够，千万别直接指向 `dataset/images/val`。

### 2.3 启动成功的标志

终端里应该看到类似输出：

```
 模型      : onnx-cpu / fire_yolov8n.onnx
 摄像头    : 图片目录 · samples
 访问地址  : http://127.0.0.1:8000/
```

并且在有火焰的帧上出现：

```
[alarm] 火情告警 #fire_smoke_20261021_151039_841：火焰 1 个 / 烟雾 1 个，最高分 0.890
```

### 2.4 命令行参数

| 参数 | 说明 | 示例 |
|---|---|---|
| `--camera` | 视频源 | `0` / `1` / `/dev/video0` / `dir:路径` / `file:路径` |
| `--port` | HTTP 端口 | `8000` |
| `--host` | 监听地址 | `0.0.0.0` |
| `--config` | 配置文件 | `configs/app.json` |
| `--backend` | 强制推理后端 | `auto` / `om` / `onnx` |

## 3. 摄像头接入与排查

### 3.1 先离线确认摄像头能被 OpenCV 打开

```bash
python -c "
import cv2
for i in range(3):
    cap = cv2.VideoCapture(i, cv2.CAP_DSHOW)   # Linux 去掉第二个参数
    ok = cap.isOpened()
    print(i, 'ok' if ok else 'fail')
    cap.release()
"
```

哪个索引打印 `ok` 就用哪个。**全 fail 说明没插摄像头或驱动没装**，软件层面无解。

Windows 上还可以查设备：

```powershell
Get-PnpDevice -Class Camera -Status OK | Select-Object FriendlyName
```

### 3.2 索引不一定从 0 开始

笔记本内置摄像头通常占 0，外接 USB 的可能是 1 或 2。反过来插拔顺序也会影响。

```bash
run_pc_preview.bat 1        # 试第 1 个
run_pc_preview.bat 2        # 试第 2 个
```

### 3.3 ⚠️ 静默回退陷阱

`configs/app.json` 里配了 `camera.fallback`，摄像头打不开时会**自动**回退播放
`samples/fire_synthetic.jpg`，页面照样有画面、照样出检测框 —— 很容易误以为摄像头通了。

**判断方法**：看页面左上角的视频源标签，出现 `回退演示 · ...` 就是回退状态。
答辩前务必确认这一行不是"回退演示"。

### 3.4 板端路径

板端（Linux）摄像头是 `/dev/video0`，两种写法都支持：

```bash
python app/main.py --camera 0 --port 8000
python app/main.py --camera /dev/video0 --port 8000
```

## 4. 界面怎么读

### 4.1 五个指标卡

| 卡片 | 含义 | 正常值 |
|---|---|---|
| 火焰目标 | 当前帧 fire 框数量 | 0（无火）|
| 烟雾目标 | 当前帧 smoke 框数量 | 0（无烟）|
| 最高置信度 | 本帧所有框里的最高分 | — |
| 推理延迟 | 单帧端到端耗时 | PC CPU 10~20 ms |
| 火情告警 | 当前告警等级 | 安全 / 烟雾预警 / 火情告警 |

### 4.2 画面上的元素

- **红色框** = 火焰，**蓝色框** = 烟雾，框角标是"火焰 78%"这样的类别 + 置信度；
- 顶部状态条：`安全`（灰）/ `检测到烟雾`（琥珀）/ `检测到明火`（红）；
- 状态条右侧是逐类计数 chip；
- 右上角 `LIVE` 表示 SSE 流在线。

### 4.3 分级告警行为（重点）

| 触发条件 | 告警等级 | 颜色 | 说明 |
|---|---|---|---|
| 火焰 ≥ 0.45，连续 1 帧 | 火情告警（二级） | 红 | 立即触发，不等 |
| 烟雾 ≥ 0.35，连续 3 帧 | 烟雾预警（一级） | 琥珀 | 过滤蒸汽/雾霾/眩光的单帧误报 |
| 已有烟雾预警时出现火焰 | 升级为火情告警（二级） | 红 | 不受 10 秒冷却限制，立即升级 |
| 连续 6 秒无目标 | 回落为安全 | 灰 | `hold_seconds` |
| 同一等级重复触发 | 抑制 | — | `cooldown_seconds=10` |

告警时自动把**带框截图**存进 `data/events/`，右侧"告警 / 证据"列表可点开。

### 4.4 手动操作

- **截图**：按钮存当前帧，同样进证据列表；
- **清除告警**：立刻把等级重置为安全（不影响后续再触发）。

## 5. 改配置（不写代码）

所有可调参数都在 `configs/app.json`，改完**重启服务**生效。

### 5.1 常用参数

| 位置 | 参数 | 作用 | 建议 |
|---|---|---|---|
| `camera.source` | `"0"` | 视频源 | 见第 2、3 节 |
| `camera.fallback` | `file:samples/...` | 打不开时的兜底源 | 想让它直接报错就删掉这行 |
| `model.backend` | `auto` | 自动选 OM→ONNX→占位 | 板端保持 auto |
| `model.conf_threshold` | `0.35` | 模型层置信度下限 | 影响所有框 |
| `alarm.thresholds.fire` | `0.45` | 火焰告警阈值 | 调低 → 更敏感但误报多 |
| `alarm.thresholds.smoke` | `0.35` | 烟雾告警阈值 | 有 3 帧确认兜底，可放宽 |
| `alarm.confirm_frames.smoke` | `3` | 烟雾连续帧数 | 调到 5 更稳，但告警更慢 |
| `alarm.cooldown_seconds` | `10` | 同级重复告警间隔 | 演示时调大避免刷屏 |
| `alarm.hold_seconds` | `6` | 无目标后多久回落 | 太短会闪断 |
| `stream.max_fps` | `15` | 推给浏览器的帧率 | 带宽不够就降 |

### 5.2 ⚠️ 三处必须对齐

类别数、类别顺序在三个地方各存了一份，**任何一个对不上都会导致框标错或推理报错**：

| 文件 | 字段 |
|---|---|
| `models/labels.txt` | 每行一个类名：`fire` / `smoke` |
| `configs/app.json` → `alarm.class_names` | `["fire", "smoke"]` |
| `configs/dataset.yaml` → `names` | `0: fire` / `1: smoke` |

风险点：**顺序**，不是数量。`fire` 必须是 0、`smoke` 必须是 1，与训练时一致。
运行 `python -m unittest tests.test_consistency` 可以自动校验这三处是否一致。

另外 ONNX 后端启动时会检查模型输出列数是否匹配 `labels.txt`，不匹配直接抛错而不是
默默画错框 —— 这个检查是有意为之，别去绕过它。

## 6. 训练自己的模型

### 6.1 准备数据集

已内置 D-Fire 导入脚本，支持三种来源：

```bash
# 1) 本地压缩包
python training/download_dataset.py --zip D-Fire.zip --out dataset

# 2) 已解压的目录（推荐，会保留官方 train/val/test 划分）
python training/download_dataset.py --dir .cache/datasets/DFire-split/DFire-split --out dataset

# 3) 直接给 URL
python training/download_dataset.py --url https://example.com/DFire.zip --out dataset
```

脚本会自动完成：识别目录布局 → 递归配对图片与同名 `.txt` → **按类名重映射 class_id**
→ 校验坐标合法性（越界框丢弃）→ 写入 `dataset/` → 生成 `configs/dataset.yaml`。

导入完会打印校验报告，形如：

```
[dataset] 图片=17221 框=21350 负样本=7833 错误=14
```

`错误=14` 是坐标越界被拒绝的标注，不影响使用。报告落在 `dataset/source_report.json`，
里面记录了重映射表，答辩被问"类别顺序怎么保证的"可以直接拿这个。

> **为什么要重映射**：不同镜像源的 `data.yaml` 类别顺序可能相反（有的是
> `0=smoke,1=fire`），脚本按**类名**而不是按 id 映射，因此不受影响。

### 6.2 训练

```bash
python training/train.py --device 0 --epochs 100
```

参数全部集中在 `configs/train.yaml`，命令行可以覆盖任意项：

```bash
python training/train.py --epochs 50 --batch 16 --imgsz 960 --name exp960
python training/train.py --smoke          # 1 epoch 跑通流程，验证代码没坏
```

耗时参考：RTX 4090、21,527 张、640 尺寸、batch 64 → **约 3 小时 / 100 轮**。

关键参数说明：

| 参数 | 值 | 为什么 |
|---|---|---|
| `optimizer` | SGD | 见 FAQ 第 2 条，`auto` 会把 lr 放大到 0.03 |
| `lr0` | 0.01 | 配 batch 64 的标准值 |
| `cos_lr` | true | 余弦退火，末段收敛更稳 |
| `close_mosaic` | 15 | 最后 15 轮关掉 mosaic，让小目标定位收敛 |
| `flipud` | 0.0 | 倒挂的火焰不存在 |
| `hsv_h` | 0.015 | 压低色相扰动，避免把橙色扰动成别的颜色 |
| `cache` | disk | 21k 图存内存要 4~6GB，内存不够就 `false` |

中断后想接着跑（已训练过的 epoch 不会重来）：

```bash
python training/train.py --model runs/fire/yolov8n_fire/weights/last.pt --resume
```

产物在 `runs/fire/<name>/`：
- `weights/best.pt`、`weights/last.pt`
- `metrics.json`（含 `per_class` 逐类指标）
- `results.csv`、`results.png`、`confusion_matrix*.png`、`BoxPR_curve.png`

### 6.3 评估

```bash
# 验证集
python training/evaluate.py --weights runs/fire/yolov8n_fire/weights/best.pt --split val

# 测试集（报告要引用这个，训练全程没碰过）
python training/evaluate.py --weights runs/fire/yolov8n_fire/weights/best.pt --split test
```

结果写 `runs/eval/metrics_<时间戳>.json`，控制台会逐类打印 P / R / mAP50 / mAP50-95。

### 6.4 标定置信度阈值

```bash
python training/sweep_conf.py --weights runs/fire/yolov8n_fire/weights/best.pt --split val
```

扫 9 个 conf 档位，输出逐类 P/R 表，并给出"recall ≥ 0.90 的最低 conf"作为建议。
结果写 `runs/eval/conf_sweep_<时间戳>.json`。

拿到表之后**自己决定**写进 `configs/app.json` 的值。当前项目的取值：

- `fire = 0.45`：火焰单帧直接告警且会存证，误报代价高，取偏精确一侧；
- `smoke = 0.35`：有连续 3 帧确认兜底，可以放宽换召回。

### 6.5 导出 ONNX

```bash
python training/export_onnx.py --weights runs/fire/yolov8n_fire/weights/best.pt
```

固定 `batch=1`、`dynamic=False`、`opset=12`，输出 `models/fire_yolov8n.onnx`，
同时写 `models/fire_yolov8n.meta.json`（输入尺寸、类别、SHA-256）。脚本末尾会跑一遍
ONNX checker，看到 `[ok] ONNX checker 通过` 才算成功。

**换模型后记得改 `models/labels.txt`**，或者加 `--sync-labels` 让脚本按训练时的
`names` 自动重写。

### 6.6 验证导出结果

```bash
# 推理速度（PC CPU）
python training/benchmark.py --model models/fire_yolov8n.onnx --runs 30

# 直接拿新模型跑网页（先用单张图，最快验证）
python app/main.py --camera "file:dataset/images/val/WEB05562.jpg" --port 8000
```

> ⚠️ **不要把 `dir:` 指向整个数据集目录**。`dir:` 源是把图片一次性全读进内存的，
> val 那 3445 张（1024×576）实测要 5 GB 以上，PC 上会卡死、板子上直接 OOM。
> 代码里已限制最多载入 200 张（`app/camera.py` 的 `MAX_DIR_IMAGES`），超过会打印提示
> 并截断，但正确做法是自己先挑十几张拷到一个小目录再指过去。

```bash
mkdir -p .tmp/demo && cp dataset/images/val/WEB05562.jpg .tmp/demo/
python app/main.py --camera "dir:.tmp/demo" --port 8000
```

## 7. 上板部署

前提：板子已联网、能 `ssh root@<板IP>`、CANN Toolkit 已预装（DK A2 官方镜像自带）。

### 7.1 PC 端打包

```bash
# OM 还没转出来时，先用这个验证打包流程
python deployment/package_for_board.py --allow-missing-model

# OM 已就绪的正式包
python deployment/package_for_board.py --model models/fire_yolov8n.om
```

产物：`dist/atlas_fire_board_<时间戳>.tar.gz`（约 14 MB）。
包内只含 `app/`、`configs/`、`models/`、`deployment/`、`docs/`、`requirements/`，
**不含** `dataset/`、`runs/`、`training/`、`tests/`、`tools/` —— 4GB 内存的板子塞不下
3GB 数据集，这个排除是硬要求。

### 7.2 传到板子

```bash
scp dist/atlas_fire_board_*.tar.gz root@<板IP>:/home/root/
ssh root@<板IP>
cd /home/root && tar -xzf atlas_fire_board_*.tar.gz && cd atlas_fire
```

### 7.3 ONNX → OM（关键一步）

```bash
bash deployment/convert_om.sh
```

脚本已封装好参数：`--framework=5`、`--input_shape=images:1,3,640,640`、
`--soc_version=Ascend310B4`、`--precision_mode=allow_fp32_to_fp16`。

- **耗时**：5~15 分钟，一次性投入（ATC 是纯 CPU 编译，不吃 NPU）；
- **内存**：峰值 2~3 GB，转换前先 `free -h` 确认，必要时停掉 Web 服务；
- **成功标志**：`models/fire_yolov8n.om` 生成，脚本会 `ls -lh` 打印大小。

> 不转 OM 也能跑，但会回退到 CPU 跑 ONNX，**大约每秒 1 帧**（估算值，未实测）。
> 1 FPS 下烟雾的"连续 3 帧确认"要等 3 秒，`hold_seconds=6` 实际只有 6 帧，告警逻辑
> 基本失去意义。所以这一步不是可选项。

### 7.4 装依赖并启动

```bash
bash deployment/install_board.sh   # 创建 .venv 装 board.txt，不含 torch
bash deployment/start.sh           # 自动 source CANN 环境变量
```

浏览器访问 `http://<板IP>:8000`。

也可以注册成开机自启：

```bash
cp deployment/atlas-fire.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now atlas-fire
```

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `No Python at 'C:\Users\...'` | 用了坏的 `.venv` | 改用 `.venv-train` |
| 训练卡在 `Downloading yolo26n.pt` | ultralytics 做 AMP 检查时联网下模型 | 预先放一个 `yolo26n.pt` 到项目根目录 |
| `ModuleNotFoundError: polars` | ultralytics 8.4 保存模型时读 csv | `pip install polars` |
| `Dataset '...' images not found` | `data.yaml` 里 `path` 用了相对路径 | 必须写**绝对路径**，`prepare_dataset.py` 已处理，手改 yaml 时注意 |
| `cv2.imread` 返回 None（中文路径） | OpenCV 不支持非 ASCII 路径 | 用 `np.fromfile + cv2.imdecode`，项目内已统一封装 |
| 训练 loss 前几轮暴涨 | `optimizer: auto` 把 lr 放大到 0.03 | 显式写 `optimizer: SGD` + `lr0: 0.01` |
| 摄像头通了但画面是合成图 | 触发了 `camera.fallback` 静默回退 | 看左上角标签，检查摄像头索引 |
| 框标错了类别 | `labels.txt` 顺序与训练时 `names` 不一致 | 跑 `python -m unittest tests.test_consistency` |
| `/api/health` 显示 `onnx` 而非 `ascend-om` | 没转 OM / OM 路径不对 / CANN 未 source | `bash deployment/convert_om.sh`，确认 `models/*.om` 存在 |
| ATC 报内存不足 | 峰值 2~3GB，板子只有 4GB | 停掉其它进程，`free -h` 确认可用内存 |
| 板端页面卡顿 | SSE 推流帧率过高 | 调低 `stream.max_fps` 或 `jpeg_quality` |

## 9. 目录说明

```
edge_fire/
├─ app/                  板端 + PC 共用的运行时代码

│  └─ web/                前端（原生 JS，无构建步骤）
├─ configs/
│  ├─ app.json            运行时配置（阈值、相机、推流）
│  ├─ train.yaml          训练超参
│  └─ dataset.yaml        数据集路径与类别（自动生成）
├─ training/              训练/评估/导出/标定脚本（不进板端包）
```
